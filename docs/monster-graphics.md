# Wizardry FC: モンスター画像データ

対象SHA256: `38da945c819fab8255a1b3b8ad7c7ea162b51e8f09584501626d0aaa14a92e9a`

以下は参考サイトの米国版アドレスを転記したものではなく、対象ROMの逆アセンブルと実行結果から特定した情報です。

## 描画の入り口

`PRG bank 3 / CPU $8000`（ファイル `0x00C010`）がモンスターの描画用OAMバッファを構築します。
入力は `$7AD2` のモンスターIDと `$0238` の識別状態（0:不確定、非0:確定）です。

| 内容 | CPUアドレス | ファイル位置 |
|---|---|---|
| 不確定時の画像セレクタ | `$80C7 + ID` | `0x00C0D7 + ID` |
| 確定時の画像セレクタ | `$812E + ID` | `0x00C13E + ID` |
| 画像ポインタ表 | `$8195 + selector` | `0x00C1A5 + selector` |
| 配置レコード領域の先頭 | `$827D` | `0x00C28D` |

selectorは偶数で、ポインタ表の**バイトオフセット**です。
ポインタはリトルエンディアンの16 bit CPUアドレスです。
ID 0～100、2状態の202参照から114個の異なる配置レコードを確認しました。

## 配置レコード

1. flags: 下位5 bitが4 KiB CHRバンク番号、上位2 bitがタイル番号のbit 6～7。
2. x補正: 原点Xは `8 + x補正`（8 bit）。
3. y補正: OAM原点Yは `0x4F + y補正 + 前の加算のcarry`（8 bit）。表示Yはさらに1を足す。
4. 追加配置数 N。
5. N個の追加配置: `x相対位置, y相対位置, token` 各1 byte。原点との加算は8 bit。
6. 8行×最大8列の配置グリッド。以下のtokenを順に読む。
7. スプライト用4パレット×4色の16 bytes。

### グリッドのtoken

| 値 | 意味 |
|---|---|
| 0, 1 | 空セル。Xを8進める |
| 2, 3 | その行の残りを省略して次の行へ |
| 4以上 | スプライトを配置。Xを8進める |

タイル番号は `(token >> 2) OR (flags & 0xC0)`、パレット番号は `token & 3`。
追加配置のtokenにもこの変換を使用しますが、追加配置では0～3も通常のタイル値として扱います。
このルーチンが設定するスプライト属性には反転や背景の後ろに置く指定はありません。

元CHRタイルのファイル位置は `0x020010 + CHRバンク × 4096 + タイル番号 × 16`。
タイルは8×8、2bpp planarです。色インデックス0は透過、1～3は対応パレットのNES色インデックスを参照します。
RGB変換は確認用の固定表で、実機の信号を厳密に再現するものではありません。

## 出力バッファと実行照合

ROMの処理はOAMバッファ `$0704` から `Y, tile, attributes, X` の順で書き込みます。
OAMの先頭1エントリは予約されており、この描画ルーチンでは書き換えません。
使用終端を `$1A`、CHRバンク番号を `$44`、パレット16 bytesを `$70～$7F` へ書き込みます。
NMI処理でCHRバンク切り替えとOAM DMAが行われます。

`verify_monsters.py` は各ケースを独立したRAM状態で開始し、スタックに戻り先を設定して `$8000` を実行します。
20000命令以内の復帰を確認し、上記4種類の出力を抽出器の結果と比較します。全202ケース一致を確認しています。
確認した最大スプライト数は56個です。

## 名前と新規ゲーム実装用のデータ

モンスターレコードはPRG bank 5のファイル `0x014010 + ID × 128` にあります。
今回取得した英語名はオフセット `0x20` の長さと `0x21` からの文字列、不確定名はオフセット0の長さと1からの文字列です。
0～9は数字、`0x0A～0x23` はA～Z、`0x24` は空白です。
未対応の文字は推測で置換せず `{XX}` 形式に残し、元のコード列も保存します。
日本語名のデコードは今回の範囲に含めていません。

`monsters.json` の各variantには以下を保存します。

- `bounds`: 元の256×240画面での `[left, top, width, height]`。透過余白を切り取る前の配置へ戻すために使う。
- `atlas_rect`: `atlas.png` 上の `[x, y, width, height]`。各個別PNGと同じ画素が入る。
- `sprites`: 各タイルの座標・色・元ROM位置。ROMから直接描画する実装にも使える。
- `layout_rom_offset` / `record_size`: 配置レコードの元ROM位置と長さ。
- `palette`: ROMに格納された16個のNES色インデックス。

これにより、新規ゲーム側はROMのCPU処理を実行せずに画像を描画できます。
