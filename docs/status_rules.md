# 状態・治療・蘇生と乱数の独立実装

`tools/status_rules.py` に状態表示のデータ抽出、DIALKO/LATUMOFIS/MADI、DI/KADORTOの対象決定後の処理を追加した。`tools/game_rng.py` は今回必要になった乱数の状態更新と範囲変換を実装する。いずれもCPUエミュレーターを必要としない。

## 状態の意味

ROMの英日表示テーブルから読み出した。3作品とも順番は共通。

|コード|意味|ROM内の日本語表記|
|---:|---|---|
|0|正常|OK / Ok|
|1|睡眠|ねむっている|
|2|恐怖|おそれている|
|3|麻痺|まひしている|
|4|石化|いしになった|
|5|死亡|しんでいる|
|6|灰|はいになった|
|7|喪失|うしなわれた|

毒は別のバイトで管理され、状態コード8ではない。表示用テーブルの8番目（0始まり）は毒のラベルで、状態0かつ毒の値が非0なら、このラベルを表示する。状態1〜7は、毒が併存していても状態のラベルを優先する。

|作品|英語ラベル先頭ROM位置|日本語ラベル先頭ROM位置|1行|
|---|---|---|---:|
|I|0x278D|0x678D|6バイト|
|II|0x1F72F|0x1F77F|8バイト|
|III|0x1F7B3|0x1F803|8バイト|

JSONの `rules.status` にラベル・元のコード配列・ROM位置を保持。Iの英語ラベル中の35は横棒として表示する。II/IIIの表には10番目に短い麻痺表記もあるが、今回の一覧は通常の8文字表示を対象とする。

## 治療

`cure(game, spell, state)` は新しい状態を返し、入力を変更しない。状態は `status`, `poison`, `hp`, `max_hp`, `vitality` を持つ辞書。

|呪文|処理|作品差|
|---|---|---|
|DIALKO|状態0〜3を0へ。毒・HPは変えない|3作品共通|
|LATUMOFIS|毒の値を0へ。状態・HPは変えない|Iは状態5以上も対象。II/IIIは状態0〜4のみ|
|MADI|状態0〜4なら状態0・毒0・HPを最大値へ|3作品共通|

「石化まで治療するMADI」と「石化は治療しないDIALKO」を区別する。正常時へのDIALKOのメッセージの違いなど、表示上の成否はこの関数に含めない。

主なハンドラー（PRG bank I=2×16KiB、II/III=12×8KiB）:

|作品|DIALKO|LATUMOFIS|MADI|
|---|---|---|---|
|I|AB93|ABB8|AC9C|
|II|94A6|9506|936B|
|III|9486|94E6|934E|

Iはキャンプでもこのハンドラーは作業用の戦闘配列を読み書きする。II/IIIはキャンプではキャラクターレコード、戦闘中は戦闘配列を操作する。検証は両場面を実行し、同じ5フィールドに正規化して比較した。完全なキャラクターの読み込み/書き戻し処理は別。

## 蘇生

`resurrect(game, spell, state, counter, accumulator, context)` は新しい状態、更新後の乱数状態、試行・成功の有無を返す。DIの対象は死亡、KADORTOは死亡・灰。死亡以上の入力HPは0を前提とする。

|項目|I|II / III|
|---|---|---|
|乱数の範囲変換|CDDAで25未満|F028 / ED10で100未満|
|成功比較|変換結果 ≤ 試行前の生命力|変換結果 ≤ 4×(試行前の生命力−1)|
|生命力の低下|成功時だけ−1|生命力4以上なら試行前に−1、失敗しても戻らない|
|生命力4未満|乱数なしで状態を1段階悪化|乱数なしで喪失へ|
|通常の失敗|死亡→灰、灰→喪失|死亡→灰、灰→喪失|
|成功時の毒|0へ|値を保持|

成功すると状態0になり、DIはHP1、KADORTOは最大HPになる。II/IIIの戦闘中のKADORTOは状態5・6のみを対象に、同じ生命力・乱数判定を行う。II/IIIのDIハンドラーは戦闘中に効果を実行しない。IのDI/KADORTOは既存の使用場面表でキャンプのみなので、独立実装と照合もキャンプに限定した。ハンドラーの対応場面は、メニューからいつ選べるかを全面的に保証するものではない。

|作品|DI|KADORTO|共通判定付近|
|---|---|---|---|
|I|ADF5|ADD1|AE0C〜AE6D|
|II|96D0|9704|971C〜97D1|
|III|96A4|96D8|96F0〜97A5|

生命力0〜22、HP0〜32767の範囲を実装上の入力範囲とし、蘇生では最大HPは正値とする。未確認の範囲や、死亡しているのに現在HPが非0の入力を拒否する。毒の値が何ターンのダメージやどんな強度を表すかは未解析。

## 乱数

3作品とも、2バイトの状態更新そのものは同じだった。counterを1増やし、旧counterをaccumulatorへ加算し、counterが255から0へ戻るときはさらに1を加える。全65,536初期状態を作品ごとの原作コードと比較した。

範囲変換は作品別に扱う。II/IIIは更新後accumulatorの8ビットを使い、今回照合した範囲では `floor(byte × limit / 256)` に一致する。Iは更新後の2バイトとバイト単位の繰り上がり処理を使うため、広い整数の乗算に置き換えると一致しない場合がある。例えば初期counter=17、accumulator=255、limit=255では、原作と移植コードは14を返す。Iはそのバイト演算を保って移植した。

```python
from status_rules import resurrect

state = dict(status=5, poison=1, hp=0, max_hp=100, vitality=18)
result = resurrect('wiz3', 'DI', state, counter=0, accumulator=0, context='camp')
# 成功例: 状態0・HP1・生命力17。IIIなので毒1は残る。
# result['rng'] を次回の乱数入力として保持する。
```

乱数がどの操作で何回消費されるかをゲーム全体で再現したものではない。戦闘命中や他の乱数分布へ今回のモデルを一律に適用しない。

## 照合範囲

`verify_status_rules.py` は実際のROMコードを実行する。メッセージルーチンへ移る直前で止め、治療・蘇生結果と乱数状態を比較する。Iの表示は日英ラベルのポインター表、II/IIIの表示は実際の表示選択処理を実行し、文字出力先へ渡るコード列を取り出して照合した。文字出力処理自体と画面の見た目は未検証。

合計251,594ケース:

- 乱数状態更新196,608（各作品65,536）
- 範囲変換12,288（4種類のcounter、accumulator全256値、limit 1/25/100/255、3作品）
- 状態表示82
- 治療1,296（3呪文×2場面×8状態×3毒値×3HP境界×3作品）
- 蘇生41,320（対象状態、生命力3/4/18/22、全accumulator値、counterの繰り上がり、非対象状態を含む）

出力は各作品の `items_spells/status_verification.json`。抽出JSONと検索ページにも状態・治療・蘇生情報を反映する。

```powershell
python tools/analyze_roms.py --verify
python tools/verify_status_rules.py .nes/WIZ3.NES
python -m unittest discover -s tests
node tests/check_item_spell_ui.cjs
```

睡眠/沈黙を付与する3呪文と抵抗判定は [afflictions.md](afflictions.md) に追加した。他の状態異常攻撃・自然回復・毒ダメージ、詠唱可能条件、呪文回数の消費、完全な戦闘ターンは残る。対象決定後の処理を、これらと混同しない。
