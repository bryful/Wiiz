# Wiz1日本版の通常攻撃

`tools/combat_rules.py` と `web/explorer/combat-rules.js` は命中計算の独立実装。日本版ROMの命令列と照合した。調査の入口は米国版の[敵への攻撃](https://taotao54321.github.io/appsouko/work/Game/Wiz1_NES/battle_fight.html)・[敵からの攻撃](https://taotao54321.github.io/appsouko/work/Game/Wiz1_NES/battle_fight_enemy.html)の資料であり、アドレスや仕様を無条件に日本版へ流用していない。

## 味方の基礎攻撃値

日本版バンク6 `$AEFA`〜`$AFB9`。レベルは255で制限する。戦士・僧侶・侍・君主・忍者の基礎命中力は `floor(level/3)+2`、他の職業は `floor(level/5)`。力16以上で力−15、力6未満で力−6を加算する。力6〜15の補正は0。

基礎攻撃回数は戦士・侍・君主が `floor(level/5)+1`、忍者が `floor(level/5)+2`（いずれも上限10）。他の職業は1。武器の最低攻撃回数と比較し、大きい方を使う。力16以上はダメージ追加値にも力−15を加える。

既存の装備寄与計算は保持し、新しい `party.combatSummary()` で基礎値と合成する。キャラクター詳細に表示する命中力・攻撃回数・ダイスと、戦闘が参照する値を共通にする。基礎ACは引き続き10で、忍者などの職業固有AC処理は未接続。

## 味方の命中判定

日本版 `$BD39`〜`$BD52`。`19+対象グループ番号−相手AC−命中力` を8ビット演算し、符号を解釈して0〜19へ制限し、1を加えた値をしきい値とする。0〜19の乱数がしきい値以上なら命中。最大95%、最小0%。現在は1グループだけなのでグループ番号1を使う。

8ビットの桁あふれも保持している。極端な能力値で数学的な広い整数式と結果が違う場合がある。今回の検証はこの挙動も含める。

## 敵の命中判定と原作との差異

日本版 `$F9E7`〜`$FA12`。`A=19+防御補正−参照AC−敵レベル`、`B=A−敵自身のAC` を8ビットで計算する。Bが正なら19で制限し、Bが負ならB/Aの符号とBの生値220との比較で0か19へ補正する。最後に1を加え、味方と同じ0〜19の判定へ渡す。防御コマンドはまだないので防御補正は0。

原作は参照ACの読み込みに敵の番号を使い、対象の防具ACではない領域を参照している。このプレイヤーはその参照不具合を再現せず、選択された対象の装備後ACを入力する。これは意図した原作との差異。算術ヘルパーのCPU一致と、ゲーム全体の完全一致は区別する。

敵の攻撃ダイスは、命中した時だけ次の定義へ進む。途中で外れた場合は同じダイスを次の命中で使う。敵の毒・麻痺などの追加効果と一部呪文・ブレスを接続した。範囲と暫定値は [enemy-actions.md](enemy-actions.md) を参照。タイプ別倍打・クリティカルは未接続。個別指示と素早さによる行動順は [turns.md](turns.md) を参照。

## 検証

`python tools/verify_combat.py` は保存データを使わず、ROMの算術部分を直接実行する。

|対象|ケース数|
|---|---:|
|職業・レベル・力からの基礎値|2,288|
|味方の命中しきい値|101,888|
|敵の命中しきい値|19,104|
|合計|123,280|

レベル255超・低い力・負の命中力・負のAC・8ビット境界を含めて一致。`output/combat/verification.json` にROMハッシュと結果を保存する。

`node tests/check_combat_rules.cjs` は同じ123,280入力をPythonとJSで比較し、職業・力・装備の合成、同一の攻撃乱数でも防具を着ると回避できること、外れた時の敵ダメージテーブル位置を確認する。既存の戦闘・探索・保存・UIテストも実行する。乱数系列、ターン全体、未接続の効果までROMと一致するという検証ではない。
