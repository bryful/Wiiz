# Wiz1の歩ける探索プロトタイプ

2026-10-21：保存済みの解析HTMLと関連データは`reference/`でGit管理しています（パスはリポジトリ直下基準）。以下の生成・検証コマンドは従来どおり`output/`へ出力します。

`reference/explorer/index.html` を開くと、ROMから抽出したWiz1のマップで移動できる。ファイル単体に10階層のデータ・移動コード・描画コードを埋め込み、外部スクリプトやfetchに依存しない。エミュレーターや6502 CPUは実行しない。

```powershell
python tools/build_explorer.py
# または全体再生成
python tools/analyze_roms.py
```

## 操作

|操作|キー|
|---|---|
|前進 / 後退|↑ / ↓、W / S|
|左旋回 / 右旋回|← / →、A / D|
|正面の扉を開いて1マス進む|Space|
|正面の壁を調べる|F|
|現在マスの階段を使う|Enter|

すべて画面のボタンでも操作できる。扉は開いてから前進する。隠し扉は正面を調べて発見し、扉として開く。階段はそのマスへ移動しただけでは使用せず、明示的に操作する。

入口は地下1階・東0/北0、北向き。入口の階段から地上へ戻れる。「もう一度、迷宮に入る」で探索を再開できる。地上は帰還表示のみで、街の施設は未実装。「入口へ戻る」は探索済みマップを残して入口へ移る開発用の操作。

## ROMデータと試作ルールの区別

ROMから使っているのは全10階層の壁・扉・隠し扉・暗闇・階段・解析済み転移先。壁は移動元の向き別データを参照し、両側を同じにしない。座標端は20マス周期で接続する。階段と転移先は既存の抽出・照合済みデータを使う。

以下は探索を触れる状態にするための試作仕様で、原作の動作を照合したものではない。

- 描画は新しいレイキャスト表示。ROMの壁画像・原作パレット・画面配置を再現していない。
- 扉は開いた後に1回移動すると閉じる。隠し扉の探索は暗闇以外では必ず成功する。
- 暗闇では一人称の壁とマップの壁を描かず、正面の探索も成功させない。照明呪文は未実装。
- 転移は移動後に処理し、連鎖を追う。同一位置の循環または16回の連鎖で停止する。
- 未解析イベントは種類を通知するだけ。罠・回転・ダメージ・ストーリー処理等を推測して発動しない。
- パーティ・所持品・装備・HP等のデータ保持を追加した。詳しくは [party.md](party.md)。全10階の歩行遭遇・試作戦闘・基本呪文に対応した。街と成長はまだない。

## 探索記録

「記録を保存」でブラウザーのlocalStorageへ手動保存し、「記録を読む」で戻す。位置・向き・歩数・探索済みマス・発見した隠し扉・帰還状態に加え、登録キャラクターと編成・所持品を保存する。開いた直後の扉は保存せず、読み込み時は閉じる。保存形式version 2は独自形式で、原作のセーブ互換ではない。

保存形式の版、ゲームID、ROMのSHA256、座標、方向、歩数、探索マス数、隠し扉の実データを検証してから状態を置換する。不正な記録で現在位置を壊さない。保存不可の環境では通知し、現在の探索は継続できる。file URLの保存範囲はブラウザーに依存する。

## ソース

- `web/explorer/engine.js`: 移動・扉・イベント・保存形式。Nodeからもそのまま読み込める。
- `web/explorer/ui.js`: 一人称表示、探索済みマップ、入力、保存ボタン。
- `web/explorer/view.js`: 一人称の投影と壁の交差判定。水平視野約116度、視点は現在マス中心から後方0.4マス（マス内）に置く。近い正面壁があっても左右の壁・扉が見える構図にする。プレイヤー座標と移動判定は変更しない。
- `web/explorer/index.html`: レイアウト・操作ガイド。
- `tools/build_explorer.py`: 対象ROMをハッシュ検証し、自己完結HTMLを生成する。

## 検証

```powershell
node tests/check_explorer.cjs
node tests/check_explorer_ui.cjs
node tests/check_view.cjs
```

エンジン検証では実際のROMマップを使用し、入口から地下1階の階段までの28歩を操作して、地下2階の東12/北7へ移動し、元の階段へ戻ることを確認した。加えて扉・隠し扉・片方向の壁・座標の周回・転移の循環・暗闇での探索・保存の往復・不正記録の拒否を検証。

UI検証は生成したHTML内の実スクリプトをオフラインのNode VMで実行する。キー/ボタン、10階層の描画呼び出し、暗闇/扉、地上帰還と再入場、保存/読み込み/保存失敗を確認した。描画APIはモックで、ブラウザー上の見た目・タッチ操作・localStorageの実環境動作は未検証。

キャラクター・パーティのデータモデルを探索状態と保存へ接続した。全10階の歩行遭遇・複数敵への対象選択・ハリト・ディオスを接続した。詳細は battle.md と encounters.md を参照。

投影の回帰検証では、正面壁と左右の扉を置いた同一マスを4方向から確認する。左右それぞれの扉の中心が画面内に入ること、側面の扉が十分な幅で投影されること、旋回後は同じ扉が正面になること、描画が座標を変えないこと、隠し扉・暗闇を維持することを検証する。実ブラウザーでの見た目は未検証。
