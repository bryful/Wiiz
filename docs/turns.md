# 個別指示と行動順

戦闘中は各キャラクターの「行動」「対象」を選び、「ターン実行」で進める。指示変更だけではHP・呪文回数・ターン数は変化しない。未指定の行動は選択中の敵への攻撃。「全員に攻撃を指示」「全員に逃走を指示」は指示をまとめて変更するだけで、その後にターン実行が必要。

## 行動と対象

- 攻撃：生存する敵を指定。実行時に倒されていたら次の生存敵に切り替える。
- ハリト：使えるキャラクターだけ選択可能。実行時に対象が倒されていれば次の敵に切り替える。
- ディオス：生存する仲間を指定。満タンの仲間への先行指示も可能だが、実行時にも満タン・死亡の場合は効果を発生させず回数を消費しない。
- 防御：ターン開始時点から有効。敵の命中しきい値に原作の防御補正2を加える。敵が防御者より先に行動する場合も有効。
- 逃走：そのキャラクターの手番で65%の試作判定。成功でパーティ全体が逃げ、残りの行動を中止する。複数人が逃走を指示するとそれぞれの手番で試みる。失敗時に敵の追加ターンは発生せず、予定された敵行動だけを実行する。

行動前に死亡・行動不能になった者はスキップする。勝利・全滅・逃走で残りの予定を中止し、まだ使われていない呪文回数は消費しない。敵はターン開始時に対象を決め、その対象が先に死亡していたら再照準せず行動をスキップする。

## ROM由来の行動順位

参考：[米国版の行動順資料](https://taotao54321.github.io/appsouko/work/Game/Wiz1_NES/battle_order.html)。日本版では味方の処理をバンク6 `$BF39`、素早さ補正テーブルを `$BFC0`、敵の処理を固定バンク `$DC47` で確認した。

味方は `clamp(0〜9の乱数+素早さ補正,0,9)+1`。補正は素早さ0〜3が+3、4〜5が+2、6〜7が+1、8〜14が0、15〜18が14−素早さ。19以上の能力値はこのプレイヤーでは18に制限して順位を求める。ROMテーブルの範囲外にある別データは参照しない。

敵は乱数バイトの下位3ビットに2を加え、順位2〜9を得る。順位の小さい順に行動。同順位ではパーティの並び順、その後に敵の並び順で解決する。画面には前ターンの予定順を表示する。途中で倒れた者や行動不能になった者は、その予定にいても行動しない。

`Math.random`を使うため、ROMと同じ乱数系列にはならない。敵の一部呪文・ブレス・状態異常と治療を接続した。範囲と暫定値は [enemy-actions.md](enemy-actions.md) を参照。前後列の射程は未実装。

## 実装と検証

`battle.plan()` / `planAll()` が指示を作成し、`execute()` が全指示を検証してから予定を確定・実行する。入力エラーでは乱数・HP・回数・ターン数を変更しない。`web/explorer/turn-ui.js` が個別の入力欄を描画する。旧 `attack()` / `flee()` / 直接詠唱APIは互換のため残すが、戦闘画面のボタンは指示→executeの経路だけを使う。探索中のディオスは即時発動。

`python tools/verify_combat.py` に行動順位の照合446ケースを追加した。味方は素早さ0〜18×全10乱数、敵は全256乱数。味方の乱数取得は呼び出し境界で固定値に置き換え、算術・テーブル参照をROMと比較する。敵は乱数取得後の命令を全バイト値で比較する。乱数取得器自体やターン全体のCPU一致を主張するものではない。

`node tests/check_turns.cjs` は混在する行動順・同順位・防御・死亡による中止・再照準・攻撃と回復の混在・逃走・入力検証を確認する。`check_encounter_ui.cjs` と `check_explorer_ui.cjs` では生成HTMLから指示の設定→ターン実行→戦闘終了までを確認する。UIはDOM/描画モックでの検証であり、実ブラウザーの見た目は未検証。
