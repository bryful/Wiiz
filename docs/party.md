# 探索版のキャラクター・パーティ

2026-10-21：保存済みの解析HTMLと関連データは`reference/`でGit管理しています（パスはリポジトリ直下基準）。以下の生成・検証コマンドは従来どおり`output/`へ出力します。

`reference/explorer/index.html` の下部に「パーティと所持品」を追加した。デモの戦士・僧侶・盗賊・魔術師の4人で探索を始められ、入口または地上で新しいキャラクターを登録して編成できる。

## 対応範囲

- 登録名簿20人、パーティ最大6人。名前・種族・属性・職業・レベル・能力値6種・HP・状態・毒・経験値・所持金を保持する。
- 新規作成は基本4職。作成後は空きと属性条件を満たせば自動で参加する。満員や属性不一致の場合は名簿で待機し、理由を登録欄に表示する。編成後に「参加」でパーティに入れる。「待機」は名簿へ戻すだけで削除しない。
- 作成・参加・待機は地下1階の東0/北0または地上のみ。並び順と装備は探索中も変更できる。
- 各人の所持品は最大8個。装備を外した品を、別のパーティメンバーへ渡せる。満杯の場合は、元の所持品を失わずに拒否する。
- 武器・鎧・盾・兜・籠手の5種類を装備でき、同じ種類は1品まで。呪われた装備の取り外しは拒否する。道具・装飾品の装備効果や使用操作はまだない。
- 行動可能なメンバーがいない場合は移動しない。開発用の「入口へ戻る」は引き続き使用可能。

## ROMを使う部分と試作仕様

名前・アイテムの種類・装備職業ビット・属性値・呪い値・AC寄与・攻撃補正・ダイス・最低攻撃回数・クリティカル値は既存のWiz1抽出データを使う。

暫定表示は基礎AC10・攻撃補正0・攻撃回数1・素手2d2に、装備済み品の寄与を加えたもの。Wiz1の装備寄与の加算順・符号・ダイス順序を既存のPython実装と比較した。完全な職業/レベル/能力値に基づく戦闘パラメータではないため、画面にも「暫定」と表示する。

以下は原作のキャラクター生成を解析した結果ではなく、今回の試作仕様。

- 作成時の能力値・HP・初期装備は職業別の固定値。種族は保存するが、能力値へは影響しない。
- 経験値と所持金の初期値は0。成長・転職・初期ボーナス・呪文習得・商店は未実装。
- 善と悪の同時編成を拒否する。中立は両方と組める。
- 属性が合わない品は装備UIで拒否する。原作の属性不一致時ペナルティ一式や、装備失敗時の挙動はまだ組み込んでいない。
- 装備寄与は有効な装備を選んだ後の計算のみ。所持するだけの効果、抵抗/倍打ビット、忍者の無装備時補正などは暫定表示に含めない。
- 未鑑定状態のデータは保存できるが、未鑑定名の表示・鑑定・呪いの発動/解除処理はまだない。

## 保存

保存形式をversion 2へ更新し、探索位置・探索済みマスに加え、全登録キャラクター・編成順・所持品と装備をまとめて保存する。保存キーは以前と共通で、ユーザーが「記録を保存」を押した時にだけ上書きする。

version 1の探索専用記録を読む場合は、探索位置だけを復元し、現在のパーティを保持する。version 2では名簿・メンバーID・名前・能力値・HP・所持数・装備条件・重複部位・アイテムID・属性の組合せまで検証してから復元する。探索位置が正しくてもパーティが不正なら、両方とも変更しない。

この形式は原作ROMのセーブデータ互換ではない。探索版独自のブラウザー内保存。

## 検証

```powershell
python tools/build_explorer.py
node tests/check_party.cjs
node tests/check_party_ui.cjs
node tests/check_explorer.cjs
node tests/check_explorer_ui.cjs
```

モデル検証は6人制限、並び順、受け渡し、職業・属性の制限、満杯時の無変更、呪われた装備、保存の往復、不正データの拒否、旧形式の読み込み、メンバー不在時の移動停止を確認。74種類の実際のROM装備について、JavaScriptの暫定表示計算をCPU照合済みPythonカーネルの出力と比較した。

UI検証は生成HTMLの実スクリプトをNode VM上で実行し、作成・名前のHTMLエスケープ・参加・選択・装備・受け渡し・保存/復元・入口以外での編成拒否・不正保存時の現在位置維持を確認。ブラウザー実表示の見た目や、実環境のlocalStorage動作は未検証。

手動遭遇・通常攻撃・逃走・戦闘終了の試作を接続した。詳細は battle.md を参照。全10階の遭遇テーブルと基本呪文を接続した。残り呪文回数も保存対象。旧記録では職業に応じて初期回数を補完する。
