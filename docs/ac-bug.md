# FC Wizardry I のACバグ解析

2026-10-21。日本版の手元ROMと `reference/patch/fc` の既存IPSを調査。
ROM・セーブ・アプリには変更を加えていない。IPSはメモリー上だけに適用した。

## 結論

原因は敵の打撃命中計算で、対象の番号ではなく攻撃者の番号を添字にすること。
装備ACと戦闘中のAC補正の両方が誤参照になる。単に「防具が無効」になるだけでなく、
敵自身のAC、味方の毒、隊列管理値などが命中判定へ混入する。
防御コマンドの補正は別に働くので、防御中もこの不具合は残る。

## 日本版の命令列から確認した原因

`$027C` は攻撃対象の味方番号（0～5）、`$027D` は攻撃者の敵番号（6～41）。
敵は1グループ9枠なので、敵番号は `6 + (グループ-1)*9 + (個体-1)`。
固定PRGバンクの命令列は次の通り。

```asm
F9DB  LDY #$13          ; 基準19
F9DD  LDX $027C         ; 対象の味方
F9E0  LDA $7CB0,X       ; 対象の行動
F9E3  BNE $F9E7
F9E5  LDY #$15          ; 防御なら21（回避側へ2）
F9E7  TYA
F9E8  LDY $027D         ; ここで攻撃者の番号を選んでしまう
F9EB  SEC
F9EC  SBC $7DD0,Y       ; 本来は対象の装備後AC
F9EF  SEC
F9F0  SBC $7E48         ; モンスターレベル
F9F3  STA $0F
F9F5  SEC
F9F6  SBC $7D2E,Y       ; 本来は対象の戦闘AC補正
```

`$7DD0～$7DD5` は味方6人の装備後AC。その直後の `$7DD6～$7DDB` が毒値、
`$7DDC～$7DE1` が隊列のキャラクターページ値である。
後者の `$60～$73` は訓練場レコード0～19に対応する（0起点）。

|攻撃者の位置|敵番号|最初の減算で読むアドレス|混入する値|
|---|---:|---|---|
|第1群1～6体目|6～11|$7DD6～$7DDB|味方1～6人目の毒値|
|第1群7～9体目|12～14|$7DDC～$7DDE|味方1～3人目のページ値|
|第2群1～3体目|15～17|$7DDF～$7DE1|味方4～6人目のページ値|
|第2群4体目以降|18～41|$7DE2～$7DF9|後続する別用途のRAM|

2回目の減算では、同じ敵番号により `$7D34` 以降の敵AC領域を読む。
よって正常な装備AC参照が2重に外れている。後続RAM全体の意味は今回確定していない。

## 計算と再現結果

通常の数値範囲では、原作の命中率は
`(敵LV + 誤参照値P + 敵自身のAC - 防御補正2) × 5%` に相当する。
ただし演算は8ビットで、下限・上限だけの単純なclampではない。
命令列は中間値AとBを保存し、Bの符号、`$DC`との比較、Aの符号で分岐する。
極端な値にはこの簡略式を使えない。

最終的に `$6B` に1～20のしきい値を作り、`$FA25～$FA2C` で
0～19の乱数との比較を行う。以下は乱数が均等とした公称確率であり、実戦の実測頻度ではない。

既存のpy65 1.2.0（BSD、既存依存）と既存のROMバスを利用し、
RAMを設定して日本版の `$F9DB～$FA13` を直接実行した。

|条件（特記以外は防御、味方AC10）|原作|2009年fix|2011年patch|
|---|---:|---:|---:|
|第1群先頭マーフィー、LV10・AC-3|25%|90%|90%|
|同、味方AC0|25%|40%|40%|
|同、味方AC-12|25%|0%|0%|
|同、防御しない|35%|95%|95%|
|同、敵ACを-3から6へ変更|70%|90%|90%|
|同、味方1人目の毒値4|45%|90%|90%|
|同、$0281=-2|25%|80%|90%|
|同、対象の戦闘AC補正-4|25%|70%|70%|
|第2群先頭LV6忍者、AC6、後衛ページ$60|95%|70%|70%|
|同、後衛ページ0|50%|70%|70%|

原作ではACを改善してもマーフィーの命中率が変わらず、敵ACを上げると命中率まで上がる。
また後衛がいると第2群先頭に大きな補正が混入する。
修正後は防具が弱い場合に原作より被弾が増える。修正は一律の易化ではない。

## 既存パッチの比較

### 2009年 `wizardry_pg_fc_fix.ips`

`reference/patch/fc/[090908]FC_wiz1_pg_fix` に格納。
付属readmeの命中処理変更をIPS実体の逆アセンブルでも確認した。
`X=$027C` を保ち、`$7DD0,X` と `$7D2E,X` を読むよう変更。
さらに `$0281` のマポーフィック補正を独立して減算する。
属性・倍打・逃走・罠解除等の別修正も含むため、ACだけのパッチではない。

### 2011年 `wiz1patch.ips`

`reference/patch/fc/[110807] wiz1patch (2011-08)` に格納。
AC命中処理の変更はファイルオフセット **0x1F9F9 の 7D→7C**。
これにより `$F9E8: LDY $027D` が `LDY $027C` へ変わり、2つのAC参照を同時に直す。
この命中処理には `$0281` の減算を追加しない。したがって2009年版と同一の修正ではない。
マポーフィックの全効果・別経路への影響は今回検査していない。
こちらも別のバグ修正やデータ変更を含む総合パッチ。

石垣環マンガ版風のパッチは2009年fixをベースとする旨のメモがあり、
アイテム・モンスターのバランス変更も含む。単機能パッチ01～26は追加の調整集で、
それ自体をAC修正用として扱うべきではない。

## Wiizへの意味

現在のネイティブ版は既存binjnesでROMを実行するため、未修正ROMのこの命令列もそのまま動く。
旧ブラウザー近似実装についての `docs/combat.md` の「対象ACを渡す」という説明とは区別が必要。
さらに「誤参照Pを対象ACに替える」だけで敵自身のACを残す計算は、上記2パッチの修正とも異なる。

将来修正機能を入れる場合は、既存パッチの最小変更を参考にする方法がある。
ただし既知ROMの元命令を確認し、マポーフィックを含む修正範囲を選ぶ必要がある。
今回は解析のみで、修正機能やパッチ適用は実装していない。

## 再実行・検証範囲・権利

`python tools/analyze_ac_bug.py` → `output/ac-bug-analysis.json`。
対象ROM SHA-256: `38da945c819fab8255a1b3b8ad7c7ea162b51e8f09584501626d0aaa14a92e9a`。
36敵枠×6対象×3装備AC×防御有無×3版と上表で **3,918ケース** を実行。
修正2版はこの範囲で対象ACに従い、敵位置への依存が消えることを確認した。
元ROMとIPSは書き換えず、生成JSONにはハッシュと計算結果のみを保存する。

既存CPUの命令実行による部分検証であり、バスは既存の解析用近似実装。
binjnes上の戦闘通し実行、乱数分布、全呪文経路、全8ビット境界、別ROM改訂は未検証。
表の毒値・隊列値・補正値は実行前に与えたもので、生成経路全部を今回検証したわけではない。
独自CPU・Mapperの新規実装や外部コードの取り込みはしていない。

IPS付属資料には今回確認した範囲で明示的なライセンス・再配布許諾が見当たらない。
2011年資料の作者・出典は同梱メモによる紹介で、作者本人の確認ではない。
既存パッチを製品へ同梱・移植する場合には別途権利確認が必要。
既存資料・著作権表示は保持し、今回は研究入力としての参照だけに留めた。
