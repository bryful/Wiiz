# カティノ・マニフォ・モンティノの付与処理

`tools/affliction_rules.py` に対象1体の判定と状態更新を追加。3作品のカティノ・マニフォは、原作ではどちらも**睡眠コード1**を設定する。別々に「睡眠」「麻痺」を設定する実装にはしない。モンティノは状態コードを変更せず、沈黙用のカウンターに2〜5を設定する。

この処理は対象決定・モンスターの読込・画面表示待ちを終えた後の部分。攻撃の抵抗判定・付与・消費乱数は再現するが、完全な戦闘ターンや自然回復は含まない。

## 対象と適用順序

|呪文|状態条件|成功時の更新|
|---|---|---|
|カティノ|状態0のみ|状態1、行動値FF。Iは補助行動値もFF|
|マニフォ|状態0のみ|カティノと同じ|
|モンティノ|状態0〜4|沈黙カウンターを `(次の乱数バイト AND 3) + 2` へ|

元ハンドラーのグループ初期化も照合した。味方が唱えると敵1グループの9スロットを走査する。敵側の詠唱ではIは味方6スロット、II/IIIは実際のパーティ人数となる。空スロットや死亡状態は状態条件で除外される。対象1体の付与比較は敵側スロットで実施し、味方対象への全経路は未照合。

処理順は次のとおり。

1. 状態条件に合わなければ、状態更新も乱数消費もせず次の対象へ。
2. 乱数バイトを1つ取り、魔法抵抗値と比較。
3. 抵抗されなければ、次の乱数を100未満に変換してレベル判定値と比較。
4. `判定値 < 変換後の乱数` の場合だけ付与。同値は失敗。
5. モンティノは成功時にだけ、追加の乱数バイトで沈黙カウンターを決める。

この部分の乱数消費は0〜3回。状態条件で除外した対象や、抵抗で止まった対象にも一律に乱数を振る実装にしない。表示待ちの中で起きる乱数更新や、入力待ち時間による乱数列の変化は別の範囲。

## 魔法抵抗

3作品ともまず `乱数バイト < 抵抗値` で抵抗となる。II/IIIはさらに抵抗値FFを無条件の抵抗とする。Iにはこの追加判定がないため、抵抗値255でも乱数255なら次のレベル判定へ進む。

これは百分率ではなく0〜255のバイト比較。Iで最初の判定を通っても、次の判定で失敗する場合がある。単に「抵抗255だから常に成功/失敗」とまとめない。

モンスターデータに次のフィールドを追加した。

|フィールド|Iのレコード内位置|II/IIIの統計領域内位置|
|---|---|---|
|magic_resistance_raw|0x66|18|
|status_flags_raw|0x68|20|
|katino_modifier_flag|status_flags_raw AND 0x10|同左|

原作の読込結果はIの7E69/7E6B、II/IIIの0252/0254に現れる。レベル判定に使う配列の値は、モンスターのHPダイス個数（既存の `stats.level`）から設定されていることも初期化コードで確認した。全269種について、元の読込ルーチンが出力した3フィールドを照合した。`status_flags_raw` の他のビットの意味は確定していない。

## レベル判定値

同じ式に一律変換しない。原作はバイト加減算・符号・繰り上がりで分岐し、通常の数学的なclampと異なる境界がある。

|作品|カティノ/マニフォの基本値|モンティノの基本値|元の計算部分|
|---|---:|---:|---|
|I|50|40|bank2 A54C|
|II|50|40|bank12 8F40|
|III|10|8|bank12 8F22|

Iはレベル差を5倍して基本値に加える構成。IIは基本値+対象レベルを127で飽和させてから術者レベルを引く。IIIは基本値+対象レベルを255で飽和させ、術者レベルを引いた後に5倍する。この説明だけでは、符号や借りによる例外を完全には表せないため、コードはそれぞれの分岐を保って移植した。

カティノだけは、対象モンスターのフラグ0x10が立つ場合に判定値から100を差し引く補正がある。IとII/IIIでは補正を行う位置や下限分岐も異なる。マニフォには同じ補正がない。判定値が下がると付与されやすくなるため、このフラグを「睡眠への抵抗・完全無効」と解釈せず、`katino_modifier_flag` と呼ぶ。

判定値は成功率の百分率ではない。変換後乱数との大小判定で使う値であり、100を超えることや0になることもある。Iの範囲変換は前回移植したバイト演算をそのまま使う。

## 独立コードの利用

```python
from affliction_rules import inflict

target = dict(status=0, action_raw=0x12, aux_action_raw=0x34, silence=0)
result = inflict('wiz3', 'KATINO', target,
                 caster_level=10, target_level=3,
                 resistance=0, counter=255, accumulator=255,
                 katino_modifier_flag=False)
# result['state']: 新しい対象状態。入力targetは変更しない。
# result['rng']: 次の対象/処理へ渡す乱数状態。
# result['outcome']: skipped_status / resisted / saved / applied。
```

術者/対象レベル値・抵抗値は0〜255。ここでの `aux_action_raw` はIの2つ目の行動用バイトを保持するために設け、II/IIIでは変更しない。沈黙カウンターの値2〜5が、そのまま2〜5ターン持続することまでは確認していない。

`items_spells/data.json` の該当呪文には、効果概要、状態条件、比較式、ハンドラーと補助ルーチン位置を追加した。モンスター図鑑のJSONにも上記の抵抗/フラグを追加している。

## 照合

追加612,511ケース:

- レベル判定398,336: 各作品の実際の基本値2種類×術者/対象の全256×256値。II/IIIの補正100は境界レベルを追加照合。
- 魔法抵抗196,608: 抵抗全256値×乱数全256値×3作品。
- 付与17,280: 3呪文、補正フラグ、レベル差、抵抗、状態、乱数の繰り上がり・境界を組み合わせ、更新結果と次の乱数状態を比較。
- モンスターフィールド269種、元グループ初期化18ケース。

`verify_afflictions.py` は原作の判定・乱数・更新命令を実行する。対象1体の比較では、表示待ちとメッセージだけを捕捉して復帰させ、モンスター読込後の入口から開始する。ROMのバイトを書き換えるものではない。出力は各作品の `items_spells/affliction_verification.json`。

```powershell
python tools/analyze_roms.py --verify
python tools/verify_afflictions.py .nes/WIZ3.NES
python -m unittest discover -s tests
node tests/check_item_spell_ui.cjs
```

残る範囲: 他の攻撃/状態異常呪文、睡眠・沈黙の自然回復、行動取消と行動順、戦闘メッセージ/待ち時間、完全な戦闘ターン処理。
