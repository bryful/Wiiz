# 日本語モンスター図鑑と能力値

対象は `rom_profiles.py` にSHA256を登録した3本のみです。全269種を既存の画像とIDで結び付けています。

## 共通JSON

各作品の `monsters.json` に次の項目を追加しました。

- `name_ja` / `unknown_name_ja`: 日本語の確定名・不確定名。
- `japanese_name_codes` / `japanese_unknown_name_codes`: 元ROMの文字コード列。
- `stats`: 出現数、HP、レベル、AC、攻撃回数と各攻撃ダイス、魔術師系・僧侶系の呪文レベル、経験値。
- `data_source`: レコード位置、能力値の位置、元バイト列、レコード内のフィールド位置。

ダイスは `{count, sides, bonus, expression, minimum, maximum, note}` として保存します。
通常の範囲は `count + bonus` ～ `count × sides + bonus` です。これはダイス式の範囲で、実際の戦闘での補正・上限をすべて再現するものではありません。
レベルはHPダイスの個数です。呪文は使用可能な系統レベルを示し、個々の呪文の選択処理は含みません。
経験値は3 bytesのパック10進（BCD）を上位桁から解釈します。ACは符号付き8 bitです。

## 能力値の位置

| フィールド | Wiz1: レコード先頭から | Wiz2/3: 能力値部分の先頭から |
|---|---:|---:|
| 出現数ダイス（3 bytes） | `0x42` | `0x02` |
| HPダイス（3 bytes） | `0x45` | `0x05` |
| AC | `0x48` | `0x08` |
| 攻撃回数 | `0x49` | `0x19` |
| 攻撃ダイス列（各3 bytes） | `0x4A` | `0x1A` |
| 魔術師系呪文LV | `0x62` | `0x0F` |
| 僧侶系呪文LV | `0x63` | `0x10` |
| 経験値（BCD 3 bytes） | `0x6C` | `0x16` |

Wiz1のレコードはfile `0x014010 + ID × 128`。攻撃ダイスの領域は6個分固定です。
Wiz2のレコードはfile `0x014010` のポインタ表から参照し、能力値部分はレコード+`0x32`です。
Wiz3のレコードはfile `0x00C010` のポインタ表から参照し、能力値部分はレコード+4です。
Wiz2/3の攻撃ダイス数は可変長で、HydraやCarrierの7回攻撃も保持します。

Wiz1は参考資料 [データ構造](https://taotao54321.github.io/appsouko/work/Game/Wiz1_NES/prog_struct.txt) を手掛かりに対象ROMで検証しています。
Wiz2/3はレコード読込処理で共通RAM `$0240` 以下に展開されることを確認しました。
たとえばWiz3の8 KiB PRG bank 12、CPU `$8139` と `$813F` は呪文LV、`$8174` はHPダイス、`$8187` はACを参照します。

### 特殊なダイス値

Wiz1 ID94 MAELIFICには面数0の出現数・攻撃ダイスがあります。この値は壊れたデータとして削除せず、そのまま出力します。
面数0の場合は `minimum` / `maximum` を `null` にし、図鑑に注記しています。ROM側での最終的な挙動は未確定です。

## 日本語名

Wiz1ではPRG bank 3内の日本語名ポインタ表を読みます。

- 確定名: file `0x00EFDA`（CPU `$AFCA`）。
- 不確定名: file `0x00EF10`（CPU `$AF00`）。
- 文字列は `0xFF` 終端。

フォント（CHR bank 4）を確認して独自コードを対応付けています。
`0x36` / `0x37` は半濁点・濁点で、前の文字とUnicode正規化して「パ」「バ」などに結合します。
`0x25` の特殊な塗りつぶし字形は「■」として保持し、推測で他の記号へ置換していません。

Wiz2はレコード内の固定16 bytes、Wiz3は名前ポインタ先のNUL区切り文字列（英単数・英複数・日本語）から取得します。
カタカナ部分はJIS X 0201の半角カナに対応し、ひらがな部分はROMフォントの独自配置に対応付けます。
たとえばWiz3の `EA 96 92 9F 93` は「はかいそう」です。
全269種の確定名・不確定名について未対応コードが残っていないことを確認しました。

## 検証

`verify_monster_data.py` は実際のROM読込ルーチンを実行します。

| ROM | 読込ルーチン | 英語・日本語のケース数 |
|---|---|---:|
| Wiz1 | CPU `$CFC8` | 202 |
| Wiz2 | CPU `$FF8F` | 156 |
| Wiz3 | CPU `$DE97` | 180 |

全538ケースで、能力値の元バイト列と、日本語モードの確定名・不確定名のバイト列が実行結果に一致しました。
これはROMの読み込みとの照合です。すべてのフィールドの意味やUnicode字形の正しさをCPU比較だけで証明するものではありません。

```powershell
python tools/analyze_roms.py --verify
python -m unittest discover -s tests
node tests/check_catalog_ui.cjs
```

図鑑の検索・半角カナ正規化・並び替え・呪文フィルタは、生成HTMLのJavaScriptをオフライン実行して確認します。
この環境ではブラウザ自動操作の`file:` URLが許可されていないため、実ブラウザ上のレイアウトと操作の自動確認は行っていません。
